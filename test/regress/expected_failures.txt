# PostgreSQL regression tests that fail through pg-proxy, as "test # cause: first symptom".
# TestInstallcheckThroughProxy fails if a test outside this list fails, or a
# listed test passes. Run it with PG_PROXY_REGRESS_UPDATE=1 to regenerate the
# list from a run; reasons of tests that still fail are kept.
#
# Causes (the first symptom is from regression.diffs; later tests can also
# fail because an earlier test did not clean up):
#   set-reset            SET, SET ROLE and SET SESSION AUTHORIZATION are undone after every
#                        transaction: releasing the backend connection runs RESET ALL and
#                        resets the role. Most plan differences come from SET enable_*.
#   session-leak         Session-scoped objects (temporary tables, SQL PREPARE) outlive the
#                        client session on the shared backend connection.
#   cascade-tablespace   test_setup could not create regress_tblspace (set-reset).
#   cascade-publication  The publication test left a FOR ALL TABLES publication behind
#                        (set-reset), so UPDATE and DELETE on tables without a replica
#                        identity fail.
#   unnamed-statement    The RESET ALL on release discards the unnamed prepared statement
#                        between Parse and a later Describe (psql \gdesc).
#   fastpath             FunctionCall (fastpath) messages, used by libpq's large-object
#                        functions, are rejected and the session is closed.
#   login-trigger        Login event triggers fire when the proxy opens a backend
#                        connection, not when a client connects.
