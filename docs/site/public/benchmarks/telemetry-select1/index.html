Method

  • ARM64 Linux, one pinned proxy core, PostgreSQL 16.16 and pgbench 16.16. Pool size 16, 4 pgbench workers, simple protocol.
  • Each comparison alternated baseline and candidate in three pairs. Each run used a fresh proxy, a 3-second warmup, and a 12-second measurement window.
  • The loopback fake Agent advertised a 0.1% trace keep rate, accepted client-side APM statistics, and received DogStatsD over UDP. Client-side distribution batching was active for both variants.
  • Throughput, p99 and CPU per transaction are medians of three runs. p99 is calculated from each run’s transaction log.

These runs cover synthetic SELECT 1 queries. They estimate each change’s effect independently. A combined run is needed to measure overlap.
